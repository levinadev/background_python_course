# Celery, Redis и Docker. Шаблон с правильными настройками

Шаблон к курсу [Celery и Redis. Фоновые задачи в Python и запросы к ИИ (2026)](https://stepik.org/a/296990). В нём собраны вместе настройки и приёмы, которые в курсе разбираются по отдельности. Задачи не теряются при падении воркера, письма не уходят дважды, долгая работа не задерживает быструю, расписание не запускается два раза, а запросы к нейросети переживают лимиты сервиса и не оплачиваются дважды.

Шаблон запускается одной командой. Его можно взять за основу нового проекта или перенести нужные файлы в свой.

## Что уже настроено

| Что | Зачем | Модуль курса |
|---|---|---|
| Повторы с растущей случайной паузой | тысяча упавших задач не повторится одновременно и не добьёт внешний сервис | Ошибки, повторы и надёжность |
| Защита от повторного выполнения, `once.claim` | письмо уйдёт один раз, даже если задача повторилась или запущена дважды | Ошибки, повторы и надёжность |
| `task_acks_late` и `task_reject_on_worker_lost` | задача вернётся в очередь, если воркер упал посреди работы | Ошибки, повторы и надёжность |
| `visibility_timeout` на час | неподтверждённая задача не выполнится вторым воркером раньше времени | Ошибки, повторы и надёжность |
| Лимиты времени для всех задач и свои для долгих | зависшая задача не займёт воркер навсегда | Ошибки, повторы и надёжность |
| Очереди `default` и `heavy`, `worker_prefetch_multiplier=1` | долгие отчёты не задерживают письма и короткие задачи | Воркеры, очереди и масштабирование |
| `--max-tasks-per-child` | процессы воркера не копят память | Воркеры, очереди и масштабирование |
| Цепочка `chain` из отчёта и пересказа | результат одной задачи сам уходит в следующую, каждая в своей очереди | Цепочки и группы задач |
| Один beat и замок `once.single_run` | периодическая задача не запустится дважды | Периодические задачи |
| `stop_grace_period` | при остановке воркер доделывает задачи | Мониторинг и эксплуатация |
| Flower с паролем, доступный только с вашего компьютера | видно очереди и задачи, а панель не открыта всему интернету | Мониторинг и эксплуатация |
| Redis с AOF и `noeviction` | очередь переживает перезапуск Redis, служебные ключи Celery не вытесняются | Redis для работы с Celery |
| Mailpit | письма видно в браузере, настоящим адресатам при разработке ничего не уходит | |
| `compose.rabbitmq.yaml` | переход на RabbitMQ без правки кода | Redis или RabbitMQ |
| Тесты без Redis, брокера и почты | задачи и веб-код проверяются за доли секунды | Celery в веб-приложении и тесты |
| Очередь `ai` с одним процессом, `rate_limit`, пауза из `Retry-After`, кэш ответов | нейросеть не упирается в лимит запросов, а за одинаковый запрос не нужно платить второй раз | Нейросети в фоновых задачах |
| `compose.ollama.yaml` | настоящая модель вместо учебной без правки кода | Нейросети в фоновых задачах |

## Что внутри

```text
background_python_course/
├── compose.yaml            # все сервисы
├── compose.rabbitmq.yaml   # тот же проект с брокером RabbitMQ
├── compose.ollama.yaml     # настоящая нейросеть вместо учебной
├── Dockerfile
├── requirements.txt
├── .env.example            # образец настроек
├── background/
│   ├── celery_app.py       # приложение Celery и настройки
│   ├── ai.py               # клиент нейросети, учебная модель и Ollama
│   ├── once.py             # защита от повторов и замок для расписания
│   ├── mail.py             # отправка письма по SMTP
│   ├── tasks.py            # пять образцов задач
│   └── web.py              # веб-часть на Flask и цепочка задач
└── tests/
    ├── test_tasks.py
    └── test_web.py
```

В `tasks.py` пять образцов, по одному на частый случай.

1. `fetch_json` ходит во внешний сервис и повторяет запрос, если сервис не ответил.
2. `send_email_once` отправляет письмо один раз, а если почтовый сервер недоступен, повторяет попытку через минуту.
3. `build_report` выполняет долгую работу в отдельной очереди и убирает недоделанный файл, если не уложилась в лимит времени.
4. `cleanup` запускается по расписанию каждую ночь и пропускает запуск, если прошлый ещё идёт.
5. `summarize_report` просит нейросеть пересказать отчёт. Она работает в своей очереди `ai`, ждёт столько, сколько сервис назвал в `Retry-After`, берёт повторный ответ из кэша, а после всех неудачных попыток оставляет отчёт без пересказа.

В `web.py` адрес `POST /reports/summary` запускает цепочку `build_report` и `summarize_report`. Отчёт строится в очереди `heavy`, его результат сам уходит в пересказ в очереди `ai`.

## Запуск

Нужен Docker с Docker Compose.

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps
```

Должны работать восемь сервисов. Отправьте письмо, запустите отчёт и отчёт с пересказом.

```bash
curl -X POST localhost:8000/emails -H "Content-Type: application/json" \
     -d '{"to": "you@example.com", "message_id": "welcome-1"}'
curl -X POST localhost:8000/reports
curl -X POST localhost:8000/reports/summary
curl localhost:8000/tasks/<task_id из ответа>
```

Письмо откроется в Mailpit на http://localhost:8025. Повторите первый запрос с тем же `message_id`, и второго письма не будет. Учебная нейросеть нарочно отвечает 429 примерно на треть запросов, поэтому пересказ иногда приходит через полминуты. Долю сбоев задаёт `AI_FAIL_RATE` в `.env`. Задачи и очереди видно во Flower на http://localhost:5555, логин `admin`, пароль из `FLOWER_PASSWORD`.

Логи воркеров смотрят так.

```bash
docker compose logs -f worker worker-heavy worker-ai
```

## Как перенести в свой проект

1. Скопируйте `celery_app.py` и `once.py`, а если нужны письма или нейросеть, то и `mail.py` или `ai.py`.
2. Замените `background` на имя своего пакета в `include`, `task_routes` и в командах `celery -A` в `compose.yaml`.
3. Перенесите из `compose.yaml` сервисы `redis`, `worker`, `worker-heavy`, `beat` и `flower`, а для нейросети ещё `worker-ai`.
4. Вынесите долгие операции в задачи по образцам из `tasks.py`. В задачу передавайте id, а не объекты.
5. В веб-коде вызывайте задачу через `.delay()` и сразу отдавайте клиенту id задачи.

В FastAPI задачи вызываются так же, как во Flask, через `.delay()` в обработчике.

### Django

В пакете проекта, рядом с `settings.py`, создайте `celery.py`.

```python
import os

from celery import Celery

os.environ.setdefault("DJANGO_SETTINGS_MODULE", "mysite.settings")

app = Celery("mysite")
app.config_from_object("django.conf:settings", namespace="CELERY")
app.autodiscover_tasks()
```

В `__init__.py` того же пакета подключите приложение.

```python
from .celery import app as celery_app

__all__ = ("celery_app",)
```

Настройки из `celery_app.py` переносятся в `settings.py` с приставкой `CELERY_` и заглавными буквами, например `CELERY_TASK_ACKS_LATE = True` и `CELERY_WORKER_PREFETCH_MULTIPLIER = 1`. Задачу, которая читает только что сохранённые данные, отправляйте после конца транзакции, иначе воркер может их не найти.

```python
from django.db import transaction

transaction.on_commit(lambda: send_welcome.delay(user.pk))
```

## Перед выкладкой на сервер

- Поменяйте `FLOWER_PASSWORD` и пароль RabbitMQ в `.env`. Сам `.env` в git не попадает.
- Уберите сервис `mailpit` и укажите в `.env` настройки своего почтового сервиса, образец в `.env.example`.
- Проверьте, что `stop_grace_period` воркера больше самой долгой задачи его очереди, а `visibility_timeout` больше её `time_limit`.
- Держите брокер в отдельном Redis, а не в том же, что и кеш. Кешу нужно вытеснение старых ключей, а брокеру нельзя терять ни одного.
- Запускайте beat ровно в одном экземпляре.

## Тесты

Тесты не требуют Redis, брокера и почтового сервера.

```bash
docker compose run --rm --no-deps web pytest -q
```

## RabbitMQ вместо Redis

```bash
docker compose down
docker compose -f compose.yaml -f compose.rabbitmq.yaml up -d --build
```

Redis при этом остаётся хранилищем результатов и данных приложения. Панель RabbitMQ откроется на http://localhost:15672.

## Настоящая нейросеть вместо учебной

```bash
docker compose -f compose.yaml -f compose.ollama.yaml up -d --build
docker compose -f compose.yaml -f compose.ollama.yaml exec ollama ollama pull qwen3:0.6b
```

Первая команда запускает Ollama рядом с проектом, вторая скачивает небольшую модель. После этого пересказы пишет настоящая модель. Для платного сервиса добавьте в `ai.py` свою функцию по образцу `ask_ollama`, ключ API держите в `.env`.
